     `packages/server/test/packaging.test.ts` → "clean-install artifact

     first)` (384/385 server tests; the `&&` chain stopped before the web
     suite).
   - **Root cause:** `dist/` is gitignored and `postinstall` deliberately
     does not build; the unit suite's packaging contract executes the built
     bundle, so any job that runs `npm test` without building first fails on
     a fresh runner. The CI job has always built before `npm test`; the
     guard had never executed before the first tag (release.yml is
     contract-tested structurally; B5 deferred the first tag run to
     post-merge), so the ordering bug was latent until today.
   - **Why the local gate missed it (recorded so it cannot bite again):**
     `npm test` passed locally only because `npm run test:desktop` ran in
     parallel and its `server-process.test.ts` builds the server bundle as a
     side effect — a lucky race, not a real green. Reproduced
     deterministically in a fresh worktree at the tag: `npm test` without a
     build fails with exactly the CI error.
   - **Fix (PR #34 → `e06c191`):** the guard now runs `npm run build`
     between the tag-bound gate and the unit tests (the same order as the CI
     job), pinned by a new release-contract assertion ("builds before the
     guard's unit tests"). Proven end to end in a fresh worktree: `npm ci` →
     `check:release --require-version v0.1.0` → `npm run build` →
     `npm test` = 9/9 + 385/385 + 233/233, exit 0. Audited both workflows:
     every other testing job (CI, Platform matrix, Desktop matrix, cli,

## Deviations

- **The handoff's local-gate order is unsafe as written** ("npm test" before
  "npm run build"): on a fresh tree it fails (packaging contract), and with
  `test:desktop` running in parallel it produces a false green via the
  server-process build race. The safe order is typecheck → build → test
  (what CI does); recorded here for every future session.
- The `v0.1.0` tag was moved once (`ae8fac2` → `e06c191`) after the failed
  first release run. Nothing had consumed the tag: no draft, no artifacts,
  no release. Documented here so the move is never a mystery.

  sandbox (the blob host is network-blocked, as in B5); the signed job-log
  URL was fetched through an external page fetcher instead. Same
  substitution strategy, new mechanism.
