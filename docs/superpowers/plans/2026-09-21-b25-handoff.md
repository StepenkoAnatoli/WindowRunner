## What the two fixes do (flakes proven, not guessed)

- **`90aa0ef`** — root cause of the Browser E2E failure on `bf6cdce` (run `35637909327`, `dashboard.spec.ts:51`, job `106460407441`): Playwright 1.63 `fill()` on text-type inputs runs `selectText()` then `keyboard.insertText()` in **separate protocol round-trips** (see `node_modules/playwright-core/lib/coreBundle.js`, injected fill `needsinput` branch). The dashboard's rAF-coalesced `doRender()` (`root.replaceChildren`, coalescing in `dashboard-state.ts:129-133`) can rebuild in that gap → the focused input is destroyed → focus falls to `<body>` → the insert produces **zero DOM events** (no setter/beforeinput/input) and fill still returns "done" = a silently lost keystroke ("ghost fill"). Proven with instrumented catches (`/tmp/b2base/repro3-1.log` model field, `repro4-1.log` provider-id field — victim varies). Fix: `doRender()` captures `document.activeElement` testid + `selectionStart/End` before the rebuild and re-focuses + `setSelectionRange`s after the value restore (guarded for dom-stub).
- **`ea83116`** — the B2 accessibility contract test (added in `573190c`) caught a real defect: the usage table (`nowrap` cells = 423px min width) pushed the page **73px wide at 360px** (`document.documentElement.scrollWidth = 433`) because nothing contained it; additionally `renderUsagePage` rendered an **empty table shell while `status` was still loading/error** (the empty-state guard only covered `ready`) — the intermittent trigger. Fix: table renders only with rows, wrapped in `.usage-scroll { overflow-x: auto }` (app.css + dashboard.css).
