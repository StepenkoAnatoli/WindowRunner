# Restore Kit — WindowsRunner

Companion to [`../2026-09-19-checkout-integrity-audit.md`](../2026-09-19-checkout-integrity-audit.md).

**Purpose:** turn "the source has been restored" from a claim into a mechanically checkable result.

| File | What it is |
|---|---|
| `required-paths.txt` | The 77 concrete file paths named by `README.md`, `AGENTS.md`, `RELEASE_CHECKLIST.md` and the implementation plan. 3 exist; 74 do not. This is the completeness checklist for the restored tree. |
| `verify-restore.sh` | Acceptance test. Exit code 0 means the checkout finally matches its own documentation. |

`required-paths.txt` is derived only from the repository's **tracked** documents. It excludes this audit and this kit, and it deliberately drops glob patterns (`packages/*`, `packages/{shared,server,web}`, `packages/…`) that cannot be tested as paths. Reproduce it with `git ls-files '*.md'` — **not** with a `docs/**/*.md` glob, which silently matches nothing below two levels without `globstar` (audit §17, CN-1).

## Running the check

```bash
bash docs/research/restore-kit/verify-restore.sh            # filesystem + manifest checks
bash docs/research/restore-kit/verify-restore.sh --full     # + npm ci / typecheck / test / build
bash docs/research/restore-kit/verify-restore.sh --full --boot  # + boot the server and HTTP-check it
```

**Validated against the known-bad state.** On the current docs-only commit it reports `passed: 0, failed: 6` (paths-only) and `passed: 1, failed: 9` (`--full`) and exits 1 — a harness that could not detect a state known to be broken would be worthless, so this was tested before being trusted. Note the one green light in `--full`: `npm ci` **succeeds** while the product is absent, because npm silently skips the three missing workspaces. Do not read a green install as a restored checkout.

## If the source turns out to be unrecoverable

Then this repository's README is advertising a product that does not exist, and the highest-value work is not more code but honest documentation: mark unbuilt paths as non-existent rather than "Experimental", remove the `Verified` language and the `npx windows-runner` claim (`E404` on npm), fix the two broken `README.md` links, repair `AGENTS.md`'s layout and check commands (including `npx tsc`, which resolves to a deprecated unrelated package), and drop `package.json`'s `files[]`, `bin` and `postinstall`/`prestart` hooks that guarantee failure. That is small, entirely verifiable, and it is what stops the next agent — or the next user — from repeating this audit's work.
